# UI 品質標準與發版閘門

本文件是投資組合回測網站的固定 UI 驗收基準。任何影響畫面或互動的變更，都必須在 PR 合併前完成下列自動化與人工審查；任一硬性項目失敗即不得發版。

## 1. 驗收裝置矩陣

| 類型 | 視窗尺寸 | 必驗情境 |
| --- | --- | --- |
| 小型手機 | 320 × 568 | 繁中／英文、長標籤、鍵盤與黏性執行列 |
| 一般手機 | 390 × 844 | iOS Safari 主要流程、日期欄、資產編輯、結果分頁 |
| 大型手機 | 430 × 932 | 繁中／英文、深色／淺色、安全區域 |
| 手機橫向 | 760 × 390 | 短視窗、連線視窗、執行按鈕不得遮擋操作 |
| 平板 | 760 × 1024 | 單欄與雙欄切換、表格橫向捲動 |
| 桌面 | 1440 × 900 | 五組投資組合、完整結果、滑鼠與鍵盤 |

最低支援寬度為 320px。所有尺寸都要檢查繁體中文與英文、淺色與深色模式；含瀏海或 Home Indicator 的裝置必須套用 `safe-area-inset-*`。

## 2. 硬性品質標準

### 可視性

- 頁面不得產生非預期的整頁水平捲動；允許水平捲動的表格、結果分頁與圖例必須限制在自己的容器內。
- 文字、金額、投資組合名稱及錯誤訊息不得裁切；長內容必須換行、省略或在局部容器內捲動。
- 黏性頂欄與執行列必須有足夠不透明度，不得讓後方文字穿透而影響閱讀；取得焦點的控制項不得被其遮住。
- 日期、數字、下拉選單及帶後綴欄位的外框高度、內距與水平／垂直置中必須一致。
- 深色、淺色、高對比與系統強制色彩模式都必須保留目前選取狀態、焦點與資料系列辨識。

### 互動性與無障礙

- 手機主要觸控目標至少 44 × 44 CSS px；主要表單控制項至少 48px 高。
- 每個互動元件都能以鍵盤到達，並具有清楚的 `:focus-visible` 狀態。
- 分頁需具備 `tablist`／`tab`／`tabpanel` 關聯，支援左右方向鍵、Home、End，且只有目前分頁進入 Tab 順序。
- 搜尋代碼欄需符合 combobox 模式，支援上下方向鍵、Enter 選取與 Escape 關閉。
- 對話框開啟時鎖定背景捲動、移入焦點、限制 Tab 循環、支援 Escape，關閉後還原焦點。
- 圖表需有可讀名稱；可水平捲動的資料表需能取得鍵盤焦點；狀態與錯誤需使用適當 live region。
- 使用者偏好減少動態效果時，不得執行非必要動畫或平滑捲動。

### 自適應與資料壓力

- 手機預設兩組、桌面預設五組投資組合；1–5 組及 1–20 個資產都不得破版。
- 必測空白資料、0%／100%、長代碼與長名稱、五組結果加 Benchmark、大額與負值 TWD、40 年每日資料。
- 圖表日期刻度必須依期間動態取樣；圖例與選取中的結果分頁必須可見，不能依賴固定年份或固定欄寬。
- 虛擬鍵盤、手機橫向、瀏海與底部安全區域不得遮住主要操作。

## 3. 每次 PR 的驗收閘門

1. `frontend`: lint、單元／互動／無障礙測試、production build 全數通過。
2. `backend`: Ruff、完整測試與至少 80% coverage 通過，確保 UI 變更未破壞請求契約。
3. CSS 品質契約測試確認日期雙軸置中、44px 觸控目標、黏性層不透明度、安全區域、減少動態與高對比規則仍存在。
4. 依裝置矩陣檢查主要流程：設定、資產、執行、總覽、所有結果分頁、下載、連線視窗、行動選單。
5. 檢查 `git diff --check`、production bundle 與部署頁面；正式站需載入本次 release 的資產雜湊。
6. 只有全部通過後才能合併；合併後由 release workflow 建立 tag／GitHub Release，部署完成後再驗證正式站。

## 4. 已知瀏覽器差異處理

原生日期欄位的內部排版由瀏覽器與作業系統實作。iOS WebKit 在移除原生外觀時，日期值內層若沒有明確高度，可能無法垂直置中。因此日期控制項必須同時約束外框尺寸，以及 `::-webkit-date-and-time-value`、`::-webkit-datetime-edit` 的高度、flex 對齊與文字對齊；不得只靠 `text-align` 或固定像素位移修補。
